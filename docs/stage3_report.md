以**另一套獨立實作**（逐筆迴圈，不共用系統程式）重算所有指標：

| 指標 | 最大相對誤差 |
|---|---|
| MA13 / MA34 / MA55 | < 1e-15 |
| 布林上軌 / BBW | < 1e-10 |
| BBW 百分位 | **0**（修正後，見 §3） |
| ATR14（原始價單位） | < 1e-15 |
| 週 MA13（上一完成週） | < 1e-15 |
| 週 MA13 vs 資料庫週線表 | 0 |

- **前視偏誤（真實資料）**：在 6 個隨機日期截斷資料重算，截斷日前 12 個條件欄位全部相同。
- **判斷過程範例**：2330 最近一次 E 訊號 2026-05-29（週五）。週線使用 2026-05-22 那一週（上一個已完成週），不是當週；最早模擬進場日 2026-06-01。

## 3. 驗證中發現並修正的問題

| 發現 | 影響 | 處理 |
|---|---|---|
| **BBW 百分位遇到「數學上相等」的值時，結果取決於浮點誤差**：同一個 BBW 以不同加總順序計算，最後幾位不同，`≤` 比較時一邊算入一邊不算 | 2330 的 3,254 天中有 12 天百分位差 0.83 個百分點；可能改變 20% 門檻附近的壓縮判定 | 比較時加入相對容差 1e-9，相等值一律算入；加回歸測試。本資料中修正前後訊號數相同 |
| 上一項是**公式改變**，但策略版本編號只依參數產生 | 新舊公式會共用同一版本編號，違反「公式改變必須產生新版本」 | 程式版本 `fib_bb_weekly/1` → `/2`，版本編號隨之改變；暫存庫中被覆蓋的 `/1` 指標與訊號已清除（僅開發資料庫） |
| Stage 2 報告寫「83 檔」 | 數字錯誤 | 更正為 72 檔 |

## 4. 尚未解決／限制

1. **TradingView 一致性**：Python 已依 Pine 內建函數的定義實作；但 BBW 百分位的「相等值」處理，Pine `ta.percentrank` 使用精確比較，極少數日子可能不同。Pine 腳本（Phase 7）將以相同容差自行實作百分位，並提供逐日比對工具。
2. 處置股、全額交割股未納入可交易判斷（免費資料沒有）。
3. 產業別為目前分類（非歷史），選股清單的產業欄位只供參考。
4. 開發環境只有 72 檔；全市場訊號需在使用者電腦執行 `signals compute --all`。
