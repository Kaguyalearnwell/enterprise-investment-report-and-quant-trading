### 2.1 週線對齊（Python ⇔ Pine 一致）

- 週 = ISO 週（週一至週日），只由**實際有交易的日期**組成；週 K 時間戳 = 該週最後交易日。
- 第 w 週的每一個日 K 都使用第 w−1 個週 K（若整週休市則為更早一個有交易的週）。**即使在本週最後交易日收盤也不使用本週週 K**。
- Pine 對應寫法（Phase 7 實作）：
  ```pine
  wTrend = request.security(syminfo.tickerid, "W", trendExpr[1], lookahead = barmerge.lookahead_on)
  ```
  `[1]` + `lookahead_on` 是 TradingView 官方建議的無 Repaint 寫法，在本週所有日 K 上回傳上一週已確定的值，與 Python 完全相同。
- 為何不在週五收盤使用本週週 K：雖然理論上合法，但 Pine 在即時 K 棒上會 Repaint，且週五休市時「本週最後一日」無法事先得知。採一致的保守定義，可讓兩套系統逐日交叉驗證。

### 2.2 還原價為何不會造成前視偏誤

向後還原（back-adjust）在發生新除權息時，會把**之前所有**價格乘上同一個係數。所有訊號都是比值或大小順序（均線排列、`C > UB`、BBW、百分位、斜率正負），對整段視窗的等比縮放不變；視窗跨越除息日時，正是還原要修正的缺口。因此訊號使用還原價是因果的（`test_signals_scale_invariant` 驗證）。**流動性、撮合、漲跌停、檔位、股數一律用原始價。**

## 4. 出場規格（Phase 3 實作）

符號：進場日 e，進場價 `P_e`（原始價），ATR 取訊號日 `ATR_t`（已知）。所有「價位」在還原價空間維護，使用時轉換為原始價。

```
初始停損   S0     = P_e − 2.5 · ATR_t                        進場當日起生效
R               = P_e − S0
移動停利   TS_s   = max(TS_{s−1}, HC_s − 3 · ATR_s)          HC_s = 進場後最高收盤（還原價）
有效停損   Stop_s = max(S0, TS_s)                            s 日收盤算出，s+1 日生效；只上移
趨勢破壞   C_s < MA34_s 且 C_{s−1} < MA34_{s−1}  → s+1 開盤出場
時間停損   s − e + 1 ≥ 40 且 max(HC) < P_e + 1R  → s+1 開盤出場
```

停損觸發（觸價市價單）：

```
若 O_s ≤ Stop：           成交 = O_s（跳空穿越，虧損 > 1R）
否則若 L_s ≤ Stop：       成交 = Stop
跌停鎖死（H_s = L_s = 跌停價）：無法賣出，遞延至下一個可成交日開盤
```

每日處理順序（s 日）：
1. 開盤：執行前一日收盤產生的出場（趨勢破壞、時間停損）。
2. 開盤：執行前一日收盤產生的進場（漲停、追價、資金、上限檢查）。
3. 盤中：所有持股（含當日新進場）檢查停損。進場當日即觸及停損者視為停損（保守）。
4. 收盤：更新最高收盤價、移動停利、出場條件、新訊號。

出場原因編碼：`STOP_INITIAL`、`STOP_TRAIL`、`TREND_MA34`、`TIME_STOP`、`DELISTED`、`END_OF_DATA`。

## 5. 部位規格（Phase 4 實作）

```
RiskBudget = Equity_{t} · 1%                                  （t = 訊號日收盤權益）
Shares_risk = RiskBudget / (P − S0)                           P = 實際開盤價（主）或 C_t（保守）
Shares = min( Shares_risk,
              0.10 · Equity / P,                              單一股票
              (0.25 · Equity − 同產業現有市值) / P,             產業
              (0.90 · Equity − 現有總市值) / P,                 總曝險
              (0.05 · Equity − OpenRisk) / (P − S0),           投組風險
              可用現金 / (P · (1 + 手續費率 + 滑價)) )
Shares 取整：2020-10-26 前為 1,000 股的倍數；之後為 1 股（零股另加滑價）
若 Shares = 0 → 放棄訊號並記錄原因
```

同日訊號超過可用額度時的排序（事前固定）：Phase 3 用代號排序的隨機種子作為基準；Phase 5 以相對強度排名（進階功能 B）做消融比較。

## 6. 交易成本與市場規則（Phase 4 實作）

> 費率資料日期：2026-11（研究時點）。部署前須向券商及證交所查證。

| 項目 | 規則 |
|---|---|
| 手續費 | 0.1425% × 折扣，買賣各收一次；最低 NT$20 |
| 證交稅 | 賣出 0.3%（普通股波段交易；**不適用**當沖 0.15%） |
| 漲跌幅 | 前一日收盤 ±10%（2015-06-01 前 ±7%），依檔位向內取整 |
| 檔位 | <10: 0.01；10–50: 0.05；50–100: 0.1；100–500: 0.5；500–1000: 1；≥1000: 5 |
| 漲停 | 開盤價 ≥ 漲停價 → 不成交 |
| 跌停 | 一價到底跌停 → 無法賣出 |
| 停牌 | 不成交，部位凍結；下市以最後成交價出場（代碼 `DELISTED`） |
| 部分成交 | 單筆股數上限 = 當日成交量 × 5%；超過部分不成交 |

| 情境 | 手續費／邊 | 滑價／邊 | 證交稅 | **單趟往返合計** |
|---|---|---|---|---|
| 樂觀 | 0.0428% | 0.03% | 0.3% | **≈ 0.45%** |
| 基準 | 0.0855% | 0.05% | 0.3% | **≈ 0.57%** |
| 壓力 | 0.1425% | 0.15% | 0.3% | **≈ 0.89%** |

最低手續費 NT$20 在基準情境下，對成交金額 < 約 23,400 元的交易（多為零股）會墊高成本。

## 7. 驗證規格調整

- **資料起點**：至少 2013-01，才能讓週線 MA55 在 2015-01 前完成暖機。
- **切分（約略，依實際交易日計）**：IS 2015-01 ~ 2022-02；Validation 2022-03 ~ 2024-05；OOS 2024-06 ~ 2026-11；段間 embargo 40 個交易日。
- **分層參數搜尋**（取代 10 維全網格）：
  1. 基準參數單變數敏感度：每個參數 5 點，共約 50 組。
  2. 交互作用較強的參數對做 2D 網格：（BBW 百分位 × 壓縮回看期間）、（ATR 停損 × ATR 移動停利）、（成交量倍數 × BBW 百分位）。
  3. 均線以「組」測試：(10,28,45)、(13,34,55)、(16,40,65) 及中間點。
  4. 所有試驗寫入試驗登記簿，總數用於 Deflated Sharpe 與 PBO。
